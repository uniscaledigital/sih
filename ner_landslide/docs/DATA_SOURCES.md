# Data Sources

This document outlines the origins of all data ingested into the Landslide Early Warning System. We adhere to a strict **"Real Data Only"** policy for all natural phenomena.

| Source | Purpose | Real/Simulated | Notes |
| :--- | :--- | :--- | :--- |
| **Open-Meteo** | Weather / Rainfall / Soil Moisture | **REAL** | Replaced the IMD API due to IP whitelisting restrictions. Provides live, open-access hourly precipitation, soil moisture, and weather codes. |
| **USGS** | Seismic Activity (Earthquakes) | **REAL** | Uses the official USGS FDSN event API to query recent earthquakes within the bounding box of the NER region. |
| **DEM/SRTM** | Terrain / Slope Data | **REAL** | Currently pending manual integration of massive DEM GIS files for Kohima. |
| **GSI** | Historical Landslides | **REAL** | Pending integration for ML training labels. We do not invent fake negative classes. |
| **MQTT** | Ground Vibration / IoT | **SIMULATED** | This is the **only** simulated sensor in the project, as no public real-time ground vibration feed exists for prototyping. It is explicitly labeled as simulated in the UI. |
| **PostgreSQL** | Storage | **SYSTEM** | Used with PostGIS to store geometric data (Polygons and Points) and all sensor readings. |

### Why is MQTT Simulated?
Ground vibration sensors (accelerometers, tiltmeters) are physical hardware devices installed deep within a hillslope. Since we do not have physical access to a monitored slope with public live telemetry in the NER, we must simulate the payloads generated by these devices to prove the system can ingest and react to IoT hardware data.
